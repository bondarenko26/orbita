## Инструменты

- Codex: анализ требований, проектирование, генерация сервера, интерфейса, тестов и документации. Точное имя модели в журнале не утверждается.
- Sites skill: изучение доступного способа хостинга. Стандартный вход платформы связан с ChatGPT; для независимых университетских аккаунтов реализован отдельный переносимый Node.js-сервер. Sites не использован для публикации.
- PowerShell и Node.js 24: создание файлов, запуск сервера и тестов.
- SQLite через встроенный node:sqlite: хранение данных.
- Встроенный браузер Codex и инструмент управления браузером: вход, проверка 360 px, сохранение заметки, скриншот.
- Генераторы изображений, сторонние изображения, веб-шрифты, логотип университета и внешние ИИ API не использовались. Знак «Орбиты» построен CSS. Используются системные шрифты.

## Ключевые задания и результат

- «Не макет под двух пользователей, а полностью рабочая версия дневника» → пользователи и роли в базе; администратор создаёт дополнительные аккаунты.

- «Человек с выданными правами ... добавлять секции» → роль manager, проверка владельца секции, обработка заявок на вступление.
- «Главной пусть открывается расписание на сегодняшний день» → выбор текущей московской даты при входе.

## 8 ноября 2026 — проверка критериев и полноценное администрирование

Новый запрос пользователя: проверить исходные критерии и обеспечить заполнение расписания, секций и прочей информации администратором с перспективой университетского использования.

Обнаружены пробелы версии 0.1: отсутствовало редактирование большинства записей, оценки были только демонстрационными, семестр был фиксирован, не было переноса одного занятия и выдачи готового документа.

В версии 0.2 добавлен отдельный модуль административной предметной области и интерфейс с разделами. Поля и права явно проверяются сервером. Реализованы создание/изменение справочников и данных, подгруппы, семестр, переносы/отмены, TXT-справки, блокировка и роли, журнал операций. Пустая установка позволяет начать с одного администратора без демонстрационного наполнения.

Проверка: два автоматических интеграционных сценария проходят. Первый проверяет роли и полный цикл операций; второй запускает пустую базу, сохраняет группу, перезапускает сервер и подтверждает сохранность данных и сессии. В браузере администратор нашёл занятие, изменил аудиторию с 203 на 304, сохранил и увидел запись в журнале. Мобильный вид редактора проверен на 360 px; скриншот `orbita-admin-mobile.png` рядом с проектом.

Выявленная ошибка генерации: при замене SQL-запроса кавычки вокруг «Готова» нарушили JavaScript-синтаксис. `node --check` обнаружил ошибку до запуска; строка исправлена. Это реальный пример проверки и исправления ИИ-кода.

Подготовлена честная матрица соответствия `AUDIT.md`. Публичная публикация и эксплуатационная готовность не объявляются достигнутыми.

## Исправление по обратной связи: сотрудник не видит заявки

Пользователь сообщил: студент отправляет заявку, staff её не получает. В базе найдена исходная заявка №1 — сохранение работало. Причина: основная кнопка «Заявки» у staff открывала личные заявки сотрудника, а входящие были доступны только внутри управления. Также не было уведомлений сотрудникам и автоматического обновления.

Исправлено: роль staff после входа открывает «Входящие»; этот раздел доступен в основной навигации staff/admin. Отдельный серверный endpoint доступен только этим ролям. Создание заявки и уведомлений активным сотрудникам/администраторам выполняется одной транзакцией. На открытом экране список обновляется раз в пять секунд, открытые формы ответа не перезаписываются. Переключение разделов управления получает свежие данные с сервера.

Регрессия: тест проверяет наличие новой заявки во входящих staff/admin, уведомление сотруднику и запрет студенту/руководителю читать входящие. В браузере под staff подтверждены исходная заявка №1 и автоматическое появление тестовой №2 без перезагрузки. Сотрудник ответил на тестовую, студент получил ответ и статус; исходная заявка осталась без изменений. Скриншот: `orbita-staff-inbox.png` рядом с проектом.

## Исправление входящих руководителей и отступа в профиле

Следующая обратная связь: тренер также не видел заявки; кнопка выхода студента прилегала к карточке оформления. Первое исправление покрывало только деканат — это признано и исправлено.

Входящие расширены на manager: только записи в принадлежащие руководителю секции. Администратор видит оба типа, сотрудник деканата не получает списки участников секций. Запись создаёт уведомления владельцу секции и активным администраторам в одной транзакции; повторное нажатие не создаёт дубликатов. Автообновление распространяется на оба вида заявок и учитывает отмену записи. Тренер открывает входящие сразу после входа.

Регрессия проверяет два независимых аккаунта тренеров: видимость только своих записей, запрет обработки чужих, адресность уведомлений, отсутствие дублей, принятие и отзыв заявки. Оба интеграционных сценария проходят. В рабочем браузере coach видит существующую запись Алисы в «Мастерскую дизайна»; она не менялась при проверке.

У действий профиля добавлен отдельный отступ: фактически измерено 32 px между карточкой и кнопкой выхода при ширине 360 px. Горизонтального переполнения нет. Скриншоты: `orbita-coach-inbox.png`, `orbita-profile-spacing.png` рядом с проектом.

## Публикация на Ubuntu VPS

Пользователь предоставил сервер 192.0.2.42, разрешил каталог в /opt и сообщил о работающих ботах. Пользователь самостоятельно добавил публичный SSH-ключ; пароль сервера в чат не передавался.

После проверки портов и сервисов создан `/opt/orbita`, отдельный Node.js 24.22.2, пользователь и systemd-сервис `orbita`. Системный Node.js 18 сохранён. Архив Node получен с nodejs.org и проверен по SHA-256. Тестовые аккаунты, заявки и заметки перенесены через SQLite backup API. К существующему Caddy добавлен отдельный маршрут с резервной копией конфигурации; выпущен сертификат Let's Encrypt для временного имени sslip.io.

Для чтения и продления сертификатов использована официальная документация Caddy и sslip.io. Во время проверки Windows curl не смог инициализировать локальный TLS-провайдер; внешняя проверка проведена через Node.js fetch и браузер без отключения проверки сертификата.

Первый запуск резервного копирования обнаружил ограничение доступа SQLite к WAL при sandbox-настройках systemd. Доступ backup-сервиса ограниченно расширен только на каталог данных приложения, повторный запуск прошёл integrity_check. Настроен ежедневный таймер 03:30 МСК.

Внешние проверки: HTTPS, пять ролей, Secure/HttpOnly cookie, недоступность чужой заявки, мобильное расписание. Работа существующих сервисов и контейнеров подтверждена. Скриншот: `orbita-hosted-mobile.png`. Технические детали сохранены в DEPLOYMENT.md. Независимая проверка из России без VPN не заявляется выполненной.

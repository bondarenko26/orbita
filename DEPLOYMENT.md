## Управление

```sh
systemctl status orbita
journalctl -u orbita -n 100 --no-pager
systemctl restart orbita
```

Автозапуск включён. При сбое процесс перезапускается systemd. Данные находятся вне каталога релиза, обновления исходников не должны их заменять.

## Резервные копии

Таймер `orbita-backup.timer`: ежедневно в 03:30 по Москве, со случайной задержкой до минуты. Копии находятся в `/opt/orbita/backups`. Первая успешная копия создана; выполнена SQLite integrity_check. Копии на том же сервере не защищают от потери самого VPS; внешнее хранение ещё не настроено. Автоматическая ротация пока не включена.

```sh
systemctl start orbita-backup.service
systemctl list-timers orbita-backup.timer
journalctl -u orbita-backup.service -n 20 --no-pager
```

## Обновления

1. Загрузить архив только исходников в `/opt/orbita/incoming`.
2. Распаковать в новый каталог `/opt/orbita/releases/<версия>`; не перезаписывать `data`, `backups`, `orbita.env` или действующий релиз.
3. Запустить тесты отдельным Node.js из этого каталога. Тесты создают свои временные базы.
4. Выполнить резервное копирование и проверить успех.
5. Атомарно переключить `current` на новый релиз, перезапустить только `orbita.service`.
6. Проверить HTTPS, вход, основные сценарии. При несовместимой миграции нельзя автоматически откатывать только исходники: нужен план для схемы БД.

Не запускать первоначальный install-скрипт повторно поверх существующего проекта. Не обновлять системные Node.js/Caddy/Docker ради приложения без отдельной проверки других сервисов.

## Версия 0.5: почта и удаление

Дополнительные модули: mail.mjs, deletion.mjs. Зависимость Nodemailer установлена из lock-файла. Переменные SMTP_HOST/SMTP_PORT/SMTP_USER/SMTP_PASS/SMTP_FROM хранятся в отдельном EnvironmentFile /opt/orbita/mail.env (0600), подключённом drop-in службы. PUBLIC_ORIGIN — действующий HTTPS-адрес сайта. Отсутствие SMTP не препятствует входу и работе старых пользователей; регистрация/сброс с отправкой пароля отвечают понятной ошибкой.

Очередь в mail_jobs хранит тело неотправленного письма в AES-256-GCM; ключ в DATA_DIR/mail.key (0600), его также нужно резервировать отдельно от SQLite. Отправленное/отменённое или окончательно неудачное письмо очищает тело. Перед отправкой проверяется актуальность аккаунта и временного пароля. После аварии на границе отправки/подтверждения возможна повторная доставка того же письма. Состояние sent означает принятие SMTP-сервером, не факт прочтения или доставки во «Входящие». Максимум три попытки, затем новый пароль выдаёт сотрудник.

Удаление реализовано deleted_at и представлениями live_*. На рабочем сервере миграция только добавляет поля/таблицы/представления. Существующие значения, пароли, группы и расписания должны пройти сравнение на резервной копии перед переключением. Ключ mail.key и SMTP_ENV не включать в исходный архив. Автокопия backup.mjs сохраняет ключ, если он присутствует, в отдельном файле рядом с SQLite, с правами 0600.

Развёртывание 0.5 завершено 10 ноября 2026: /opt/orbita/releases/20261110-02. Все 20 тестов прошли на Ubuntu. Перед миграцией в базе уже было 7 пользователей и 4 группы (добавления пользователя сохранены), 37 занятий, 8 оценок. Проверка копии сопоставила все старые поля всех учебных таблиц, включая хеши паролей: различий нет. Прежний первоначальный пароль admin уже не действует после пользовательской смены до обновления; действующий хеш сохранён, пароль не сбрасывался. Четыре оставшихся первоначальных тестовых аккаунта проверены через HTTPS. В браузере проверены опубликованные импорт и состояние почты на 360 px.

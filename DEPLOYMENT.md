## Управление

```sh
systemctl status orbita
journalctl -u orbita -n 100 --no-pager
systemctl restart orbita
```

Автозапуск включён. При сбое процесс перезапускается systemd. Данные находятся вне каталога релиза, обновления исходников не должны их заменять.

## Резервные копии

Таймер `orbita-backup.timer`: ежедневно в 03:30 по Москве, со случайной задержкой до минуты. Копии находятся в `/opt/orbita/backups`. Первая успешная копия создана; выполнена SQLite integrity_check. Копии на том же сервере не защищают от потери самого VPS; внешнее хранение ещё не настроено. Автоматическая ротация пока не включена.

```sh
systemctl start orbita-backup.service
systemctl list-timers orbita-backup.timer
journalctl -u orbita-backup.service -n 20 --no-pager
```

## Обновления

1. Загрузить архив только исходников в `/opt/orbita/incoming`.
2. Распаковать в новый каталог `/opt/orbita/releases/<версия>`; не перезаписывать `data`, `backups`, `orbita.env` или действующий релиз.
3. Запустить тесты отдельным Node.js из этого каталога. Тесты создают свои временные базы.
4. Выполнить резервное копирование и проверить успех.
5. Атомарно переключить `current` на новый релиз, перезапустить только `orbita.service`.
6. Проверить HTTPS, вход, основные сценарии. При несовместимой миграции нельзя автоматически откатывать только исходники: нужен план для схемы БД.

Не запускать первоначальный install-скрипт повторно поверх существующего проекта. Не обновлять системные Node.js/Caddy/Docker ради приложения без отдельной проверки других сервисов.

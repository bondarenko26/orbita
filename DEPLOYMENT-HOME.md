# Домашний сервер Орбиты

Перенос выполнен 16 ноября 2026 года. Приложение открывается по адресу https://orbita.tailc24107.ts.net/ через бесплатный Tailscale Funnel. Имя устройства в Tailscale сокращено до `orbita`; имя ОС не менялось. Домен `ts.net` привязан к устройству владельца. Для публичного доступа не нужен установленный Tailscale у посетителей.

## Где лежат файлы

- Приложение: `/home/ghost/sites/orbita/app`.
- Рабочая база SQLite и почтовая конфигурация: `/home/ghost/sites/orbita/data` (каталог 0700, файлы с секретами 0600).
- Локальные резервные копии: `/home/ghost/sites/orbita/backups`.
- Отдельные Node.js и Python, OCR и модели модерации: `/home/ghost/sites/orbita/runtime`.
- Проверенная настройка SMTP Яндекса: `/home/ghost/sites/orbita/data/mail.env`; пароль приложения не хранится в исходном коде.

В секции `[Service]` пользовательской службы `orbita` задайте `Environment=PUBLIC_ORIGIN=https://orbita.tailc24107.ts.net` (без завершающего `/`). Приложение использует этот адрес для ссылок в приглашениях и для проверки запросов из браузера. После изменения службы выполните `systemctl --user daemon-reload` и `systemctl --user restart orbita`. В кабинете администратора откройте «Управление → Отправка писем» и проверьте статус «SMTP настроен».

Приложение слушает только `127.0.0.1:3107`. Funnel принимает HTTPS и передаёт запросы локальному сервису. Веб-сервис работает от пользователя `ghost`, запущен как пользовательский systemd-сервис с автозапуском. Для него включён linger, поэтому выход из SSH не выключает сайт. Публичный Funnel запущен Tailscale в фоновом режиме и сохраняет настройку.

## Управление

```sh
systemctl --user status orbita
systemctl --user restart orbita
tailscale funnel status
systemctl --user status orbita-backup.timer
journalctl --user -u orbita -n 50 --no-pager
```

Ежедневный таймер создаёт копию базы в 03:30 по часовому поясу сервера. `backup.mjs` использует SQLite backup API и проверяет `integrity_check`. Ключ шифрования очереди почты сохраняется рядом с копией, если существует. Первая проверенная копия уже создана. Для защиты от поломки домашнего диска требуется дополнительная внешняя копия.

## Данные и проверки

Из локальной резервной копии от 8 ноября перенесены пять вымышленных пользователей, две группы, 36 занятий, восемь оценок и две заявки. Новые студенты, группы и учебные записи при переносе не создавались. Все пять ролей проверены через публичный HTTPS; оба студента получают свои оценки и заявки. Cookie входа имеет атрибут `Secure`. Проверены серверная модерация текста, OCR и модели для анкет знакомств.

**Ограничение переноса:** исходная база прежнего VPS недоступна. Его журнал развёртывания от 10 ноября фиксировал уже семь пользователей, четыре группы и 37 занятий. Поэтому домашняя база не содержит как минимум часть изменений, сделанных на VPS после 8 ноября. Старый сервер и его данные не удалялись. Если доступ восстановится, сначала сделать его копию, затем сравнить записи с домашней базой и перенести недостающие изменения без замены новых записей на домашнем сервере.

Cloudflare Quick Tunnel на этой домашней сети устанавливал соединение с сетью Cloudflare, но внешний адрес возвращал ошибки 530/502. Его сервис отключён; действующий публичный адрес предоставляется Tailscale Funnel.

## Обновление

Перед изменением базы вручную запустить `systemctl --user start orbita-backup.service` и убедиться в успешном завершении. Обновлять файлы в `app`, не затрагивая `data` и `backups`. После обновления перезапустить `orbita` и проверить вход и основные сценарии по публичному HTTPS. Для устойчивой эксплуатации следует перейти на именованный домен и внешнее резервное копирование.

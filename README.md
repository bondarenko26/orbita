# Орбита · версия 0.4

Рабочая версия цифрового деканата: https://orbita-vps.example.invalid. Развёрнута в `/opt/orbita` на Ubuntu VPS пользователя. Конкурсный концепт, не официальный сервис. Все записи вымышлены. Дизайн временный: пользователь подготовит авторские темы. Подробнее о сервере и обновлении — DEPLOYMENT.md.

## Запуск

Нужен Node.js 24 или новее. В папке проекта выполните:

```sh
npm ci --ignore-scripts
node server.mjs
```

Откройте http://127.0.0.1:3000. При первом запуске создаётся SQLite-база `data/orbita.sqlite`. Создаётся только первоначальный администратор; его случайный пароль один раз выводится в терминал. Студенты, преподаватели, группы, расписания и секции автоматически не создаются. Импортируется только предоставленная пользователем структура МГСУ. При последующих запусках данные сохраняются. Не удаляйте каталог data, если хотите сохранить изменения.

Перед запуском установите зависимости по package-lock.json командой npm ci --ignore-scripts. Интерфейс не загружает шрифты, скрипты или картинки из внешних сетей.

Каждая новая установка начинается без демонстрационных данных. Для отдельной установки задайте новый `DATA_DIR`. Переменная `DEMO_SEED` больше не включает демонстрационное наполнение. Создастся только администратор со случайным паролем, показанным в терминале. Существующая база не очищается. В панели «Управление» сначала настройте семестр, затем группы и аккаунты, после — расписание и секции.

На Windows PowerShell пример отдельной пустой установки:

```powershell
$env:DEMO_SEED='0'
$env:DATA_DIR='./data-empty'
$env:PORT='3001'
node server.mjs
```

## Уже работает

- Вход, выход и сессии для пяти ролей: студент, преподаватель, деканат, руководитель секций, администратор. Прежние пять тестовых аккаунтов на VPS сохранены, новые автоматически не создаются.
- Открытие расписания на текущую дату в часовом поясе Москвы. Недели, даты, пары/сессия, окна, личные заметки.
- Расписание по группам, повторение по дням и чётности недели, создание занятия на конкретную дату.
- Оценки и даты аттестаций, индивидуальные для каждого студента.
- Подача заявки, обработка сотрудником, ответ и уведомление.
- Каталог кружков, запись и подтверждение руководителем, принятые секции в расписании.
- Сборные и соревнования, создание новых секций и событий.
- Создание новых аккаунтов с ролью через администратора. Количество пользователей не зашито в интерфейс.
- Три временные темы, выбор хранится в аккаунте. Цвета и форма компонентов описаны CSS-переменными.
- Администратор создаёт и редактирует группы, аккаунты, расписание, секции, события, оценки, объявления и настройки семестра. Есть поиск записей.
- Блокировка аккаунта, изменение роли и пароля завершают существующие сессии. Руководитель редактирует только свои секции и события.
- Архивирование занятий/секций/событий, открытие и закрытие набора, изменение ответственного и лимита участников.
- Подгруппы и сроки действия занятий. Изменение отдельной даты, перенос или отмена с уведомлением студентов; остальные недели не меняются.
- Сотрудник готовит текст справки; после статуса «Готова» её владелец скачивает TXT-документ с отметкой «конкурсный образец».
- Журнал административных действий: кто, когда и какую запись изменил. Это журнал операций, не полная история предыдущих значений.
- Основная кнопка «Входящие» учитывает роль: staff видит обращения в деканат, manager — записи в свои секции, admin — оба типа. Staff и manager попадают туда сразу после входа. Списки автоматически проверяются каждые пять секунд; открытые формы не перезаписываются. Заявка в деканат уведомляет сотрудников закреплённого института и администраторов, запись в секцию — её руководителя и администраторов. Повторная запись не дублирует уведомления; отозванная запись исчезает из входящих.

## Безопасность

Пароли хешируются scrypt с индивидуальной случайной солью; в базе нет исходных паролей. Случайный токен сессии передаётся в HttpOnly/SameSite=Strict cookie, в базе хранится его SHA-256 хеш. Сессия действует сутки, выход удаляет её. Каждый запрос проверяет роль и владельца; идентификатор студента берётся из сессии, а не из клиентского запроса. SQL-запросы параметризованы. Вывод пользовательского текста экранируется, действует Content Security Policy. Изменяющие запросы требуют JSON и проверяют Origin, если заголовок присутствует. Есть ограничение попыток входа по сетевому адресу.

В production обязательны HTTPS и PUBLIC_ORIGIN, например `https://campus.example.ru`: тогда cookie получает Secure. Служебные ключи не используются. Не публикуйте data и административные учётные данные. Переменные окружения: PORT, HOST, DATA_DIR, PUBLIC_ORIGIN.

## Проверки

```sh
node --test tests/security.test.mjs tests/persistence.test.mjs
```

Тест создаёт отдельную временную базу: проверяет вход/выход, недоступность чужой заявки и заметки, запрет административных операций студенту, обработку справки, запись в секцию, сохранение темы, создание третьего студента, защиту от запроса с чужого Origin.

Дополнительно проверены создание новой группы и расписания с нуля, перенос одной даты, срок действия расписания, изменение оценок и секций, ограничения руководителя, закрытие набора, скачивание своего/чужого документа, адресные объявления, блокировка аккаунта, пустая установка и сохранение данных после реального перезапуска сервера.

В браузере проверены вход, переключение даты, вид расписания при 360 px, создание заметки, поиск занятия администратором, изменение аудитории с сохранением в базе, запись в журнале и мобильный вид редактора. Это не полный аудит доступности или безопасности.

## Что ещё требуется до подачи на конкурс

- Независимая проверка доступа из России без VPN и обеспечение работы VPS до 28 ноября. Публичный сайт с HTTPS уже развёрнут; используется временное имя sslip.io.
- Расписание звонков, проверка конфликтов группы/аудитории/преподавателя и предупреждение о пересечении секции с парами.
- Несколько еженедельных тренировок в одной секции и разовые отмены тренировок: сейчас у секции один еженедельный интервал, который можно редактировать.
- Загрузка готовых PDF-файлов и шаблоны документов: сейчас справка скачивается как TXT.
- Поиск/фильтры студенческого каталога по направлению.
- Авторские темы пользователя, полноценные сценарии пустых состояний и проверка всех форм на телефоне.
- Внешнее хранение и ротация резервных копий, нагрузочные тесты. Ежедневная локальная копия на VPS уже настроена. Ограничение неудачных входов учитывает доверенный loopback reverse proxy; успешные входы лимит не расходуют. SQLite пригодна для одного небольшого сервера; при горизонтальном масштабировании нужна миграция на PostgreSQL и общее хранилище сессий.
- Конкурсный документ со скриншотами всех этапов, исходный архив/репозиторий, при желании видео.

Не следует подключать текущую версию к настоящим данным университета.

Конкурсная версия — отдельная среда с вымышленными данными. Для университетского пилота требуется отдельная установка, проверка эксплуатационной готовности, назначение ответственных за данные и согласование работы с персональной информацией самим университетом. Текущая версия функциональна, но не объявляется готовой к промышленной эксплуатации.

## 9 ноября 2026 — структура МГСУ и преподаватели, версия 0.3

Источник структуры — предоставленный пользователем mgsu_structure.zip. В reference/mgsu_structure.json сохранён исходный JSON: 7 основных институтов/филиал, дополнительные ветки ИДО и аспирантуры, 41 запись направлений и 76 программ. Это исходный справочник, а не подтверждение актуальности всех программ. Неполные ветки отмечены; шаблоны курсов и групп не импортируются. Существующие записи не удаляются и не получают произвольно выбранную программу.

Порядок заполнения:
1. Администратор: «Профиль → Панель управления → Учебный семестр» — даты и понедельник первой недели.
2. «Группы» — выбрать институт, форму, уровень, направление, программу; вручную задать группу, курс и год поступления. Старые группы при редактировании нужно связать с программой МГСУ.
3. «Аккаунты» — создать деканат, затем «Права деканата» — выдать доступ к одному или нескольким институтам. Без назначения сотрудник не видит студенческие записи. Доступ можно отозвать.
4. Администратор или уполномоченный деканат создаёт студентов с фиксированной группой/подгруппой и преподавателей со своим логином, паролем и институтом. Студент самостоятельно не меняет учебную принадлежность.
5. «Назначения преподавателей» — преподаватель, дисциплина, группа/подгруппа, семестр, период и статус.
6. «Расписание» — выбрать назначение и заполнить занятие. Преподаватель автоматически видит свои занятия.
7. Преподаватель: «Журнал» — выбрать назначение и дату, отметить посещаемость, добавить или исправить оценку. Студент видит результаты в «Учёбе».

Права проверяются сервером при чтении и записи. Преподаватель работает только со своей дисциплиной и текущим составом назначенной группы/подгруппы. После перевода студента прежний преподаватель теряет доступ к его записям; сам студент сохраняет свою историю. Для использованного назначения нельзя заменить группу, дисциплину, преподавателя или период: его следует закрыть и создать новое. Посещаемость привязана к реальному занятию на выбранную дату, с учётом переносов и отмен. Пустая отметка не считается прогулом. Изменения оценок и посещаемости сохраняют автора, время и старое/новое значение.

Проверки версии 0.3: 11 тестов проходят в изолированных временных базах, включая сохранение после перезапуска, пустую установку, подмену идентификаторов, институты, подгруппы, отзыв прав, перевод студента, журнал и старые сценарии заявок/секций. В браузере при 360 px проверены выбор структуры, отметка присутствия, выставление оценки, история и появление результата у студента; горизонтального переполнения страницы нет. Учебные записи для проверки существовали только в локальной временной базе.

## 10 ноября 2026 — выдача аккаунтов и смена паролей, версия 0.4

Панель «Управление → Импорт Excel»: скачивание XLSX-шаблона с доступными сотруднику группами и институтами; загрузка заполненного листа «Аккаунты»; проверка всех строк без создания пользователей; явное подтверждение; одновременное создание всего списка. Логины и временные пароли генерируются криптографическим генератором на сервере. Можно скачать настоящий XLSX со всем списком или только с одним человеком. Пароли в XLSX — текстовые значения, формулы не формируются. После закрытия окна сервер не может показать выданный пароль снова: он хранит только scrypt-хеш. При потере файла сотрудник выдаёт новый временный пароль.

Шаблон: ФИО, Роль (Студент/Преподаватель), Группа, Подгруппа, Институт. Для студента обязательна уже настроенная группа, подгруппа необязательна, институт определяется по группе. Для преподавателя используется код института из справочного листа, а назначения групп создаются отдельно. Нет автоматического создания групп, расписаний, назначений или учебных данных. Деканат ограничен выданными институтами.

Лимиты: XLSX до 1 МБ и 200 человек; предпросмотр действует 15 минут и связан с сессией сотрудника. Проверка архива ограничивает количество файлов, распакованный размер и время обработки; макросы, внешние ссылки, формулы и нетекстовые значения в таблице аккаунтов отклоняются. Чтение Excel и подготовка паролей выполняются в worker с ограничением памяти, по одному заданию на приложение. При ошибке строки весь список остаётся несозданным. Повторы строк, существующие аккаунты с тем же ФИО и принадлежностью, повторное подтверждение и изменение прав между проверкой и созданием учитываются. Полного тёзку при необходимости можно создать вручную.

Ручное создание: в «Аккаунтах» поля логина и пароля можно оставить пустыми — система выдаст их автоматически. Введённый вручную первоначальный пароль тоже временный. Новый или сброшенный пароль действует 7 дней. При первом входе разрешены только просмотр краткой информации аккаунта, выход и смена пароля; сервер закрывает все остальные API до смены. Новый пароль — от 12 до 200 символов, без пробелов по краям, с повторным вводом и проверкой текущего. Нельзя оставить прежний пароль. В профиле доступна самостоятельная смена. Смена и сброс завершают старые сессии; смена выдаёт новую сессию текущему устройству. Пять неверных вводов текущего пароля включают ограничение на 15 минут. Сотрудник не может сбросить свой пароль административной кнопкой: для этого есть профиль.

Миграция сохраняет пароли и сессии прежних аккаунтов; обязательная смена применяется к новым аккаунтам и последующим сбросам. Персональные сведения и пароли не попадают в журналы действий, импорт хранится без исходного файла и без открытых паролей. В памяти браузера пароли доступны только в окне выдачи, пока сотрудник его не закрыл. Скачанный файл сотрудник хранит самостоятельно и передаёт каждому только его данные.

Проверка: временные базы для автоматических тестов, включая весь прежний академический функционал. В браузере подтверждены предпросмотр и создание двух вымышленных аккаунтов только в локальной проверочной среде, скачивание XLSX и точность содержащихся в нём паролей, первый вход с обязательной сменой, мобильные формы на 360 px без горизонтального переполнения. Скриншоты рядом с проектом: orbita-import-preview-mobile.png, orbita-first-login-mobile.png. Пароли опубликованных аккаунтов при проверках не менялись.

Инструменты: Codex, PowerShell, Node.js, npm, SQLite, браузер Codex. Добавлены ExcelJS 4.4.0 и yauzl 3.4.0 (MIT); для зависимости ExcelJS закреплена uuid 11.1.1 после проверки npm audit. Сведения о лицензиях — THIRD_PARTY.md. Для приложения, шаблонов и файлов выдачи не используются внешние облачные API. Шаблоны формирует сам сервер. Формат XLS поддержкой не заявляется: используйте XLSX.

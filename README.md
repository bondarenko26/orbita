# Орбита · версия 0.1

Рабочая локальная первая версия цифрового деканата. Конкурсный концепт, не официальный сервис. Все записи вымышлены. Дизайн временный: пользователь подготовит авторские темы.

## Запуск

Нужен Node.js 24 или новее. В папке проекта выполните:

```sh
node server.mjs
```

Откройте http://127.0.0.1:3000. При первом запуске создаётся SQLite-база `data/orbita.sqlite`. Пароли пяти демонстрационных аккаунтов случайно генерируются и один раз выводятся в терминал. При последующих запусках данные сохраняются. Не удаляйте каталог data, если хотите сохранить изменения.

Установка пакетов не требуется. Интерфейс не загружает шрифты, скрипты или картинки из внешних сетей.

## Уже работает

- Вход, выход, сессии, пять ролей/тестовых аккаунтов (два студента, деканат, руководитель секций, администратор).
- Открытие расписания на текущую дату в часовом поясе Москвы. Недели, даты, пары/сессия, окна, личные заметки.
- Расписание по группам, повторение по дням и чётности недели, создание занятия на конкретную дату.
- Оценки и даты аттестаций, индивидуальные для каждого студента.
- Подача заявки, обработка сотрудником, ответ и уведомление.
- Каталог кружков, запись и подтверждение руководителем, принятые секции в расписании.
- Сборные и соревнования, создание новых секций и событий.
- Создание новых аккаунтов с ролью через администратора. Количество пользователей не зашито в интерфейс.
- Три временные темы, выбор хранится в аккаунте. Цвета и форма компонентов описаны CSS-переменными.

## Безопасность

Пароли хешируются scrypt с индивидуальной случайной солью; в базе нет исходных паролей. Случайный токен сессии передаётся в HttpOnly/SameSite=Strict cookie, в базе хранится его SHA-256 хеш. Сессия действует сутки, выход удаляет её. Каждый запрос проверяет роль и владельца; идентификатор студента берётся из сессии, а не из клиентского запроса. SQL-запросы параметризованы. Вывод пользовательского текста экранируется, действует Content Security Policy. Изменяющие запросы требуют JSON и проверяют Origin, если заголовок присутствует. Есть ограничение попыток входа по сетевому адресу.

В production обязательны HTTPS и PUBLIC_ORIGIN, например `https://campus.example.ru`: тогда cookie получает Secure. Служебные ключи не используются. Не публикуйте data и административные учётные данные. Переменные окружения: PORT, HOST, DATA_DIR, PUBLIC_ORIGIN.

## Проверки

```sh
node --test tests/security.test.mjs
```

Тест создаёт отдельную временную базу: проверяет вход/выход, недоступность чужой заявки и заметки, запрет административных операций студенту, обработку справки, запись в секцию, сохранение темы, создание третьего студента, защиту от запроса с чужого Origin.

В браузере проверены вход, переключение даты, вид расписания при 360 px, создание заметки. Это не полный аудит доступности или безопасности.

## Что ещё требуется до подачи на конкурс

- Публичный хостинг, домен и HTTPS; проверка доступа из России без VPN и поддержки работы до 28 ноября. Локальная ссылка для жюри не подходит.
- Редактирование/отмена существующих занятий и секций, история переносов и уведомления об изменениях.
- Подгруппы, границы семестра и расписание звонков: сейчас учебный отсчёт привязан к осени 2026, повторяющиеся занятия не ограничены концом семестра.
- Редактирование оценок сотрудником: сейчас оценки присутствуют в тестовой базе, интерфейс ввода ещё не создан.
- Изменение ролей существующих аккаунтов, сброс паролей, журнал административных операций.
- Прикрепление готового документа и скачивание: сейчас доступен ответ сотрудника и статус.
- Поиск/фильтры каталога по направлению, уведомления о конфликте секции с парами, отмена записи.
- Авторские темы пользователя, полноценные сценарии пустых состояний и проверка всех форм на телефоне.
- Резервное копирование, эксплуатационное ограничение попыток входа с учётом reverse proxy, нагрузочные тесты. SQLite пригодна для одного небольшого сервера; при горизонтальном масштабировании нужна миграция на PostgreSQL и общее хранилище сессий.
- Конкурсный документ со скриншотами всех этапов, исходный архив/репозиторий, при желании видео.

Не следует подключать текущую версию к настоящим данным университета.
